## Краткий вывод

**Подходит для:** российских веб- и мобильных продуктов, которым нужны создание платежа, возвраты, чеки и webhooks статуса платежа.

**Не подходит без дополнительной проверки, если:** до заявки нужно знать production rate limit, SLA или окончательную комиссию.

**Итог:** у ЮKassa подробно документированы API, OpenAPI и webhooks. Коммерческие условия зависят от клиента и договора.

## Технический доступ

| Поле | Значение |
|---|---|
| Base URL | `https://api.yookassa.ru/v3/` |
| Формат | HTTPS/JSON |
| Аутентификация | HTTP Basic Auth; OAuth для отдельных партнёрских сценариев |
| OpenAPI | Официальная YAML-спецификация документирована |
| Webhooks | Платежи, возвраты, выплаты и другие события в зависимости от решения |
| Sandbox | Документированный тестовый режим; нужны credentials |

## Коммерческие ограничения

На официальной странице тарифов указано отсутствие абонентской платы и комиссия с успешных платежей. Точную комиссию нельзя считать универсальной публичной ценой API. Права хранения, кэширования, SaaS-показа, redistribution, production quotas и SLA требуют отдельного подтверждения.

## Рекомендация по сценарию

- Выбирать ЮKassa для российского веб- или мобильного продукта, где важны платёжный lifecycle и документация webhooks.
- Сравнивать с CloudPayments и Т‑Банком, если важнее банковские отношения, подписки, условия эквайринга или зачисления.
- До закупки запросить письменное коммерческое предложение и подтвердить фискальные, data и operational условия.
