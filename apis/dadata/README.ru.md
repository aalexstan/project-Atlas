## Краткий вывод

**Лучше всего подходит для:** российских продуктов, которым в одном сервисе нужны удобный ввод, нормализация, обогащение и поиск адресов, компаний и контактных данных.

**Не подходит, когда:** требуется глубокая глобальная стандартизация адресов, OAuth-авторизация от имени пользователей или планируется использовать «Подсказки» для автоматической пакетной очистки базы.

**Итог:** DaData — сильный кандидат по умолчанию для российских веб-форм, CRM/ERP, нормализации адресов и поиска компаний. Главный компромисс — сложная модель оплаты: подписочные и поштучные сервисы тарифицируются отдельно, расширенные поля зависят от тарифа, а оферта прямо запрещает использовать «Подсказки» для автоматической обработки адресов, ФИО и email.

## Что такое DaData

DaData — не один endpoint, а семейство API для работы с:

- почтовыми адресами и геокодированием;
- российскими юридическими лицами и ИП;
- банками;
- ФИО;
- телефонными номерами;
- паспортными справочными проверками;
- email;
- автомобилями и публичными справочниками;
- статистикой использования, балансом и версиями справочников.

Особенно важно различать две технические группы:

1. **«Подсказки» и поиск** — интерактивное автодополнение и поиск по идентификаторам.
2. **«Стандартизация»** — серверная автоматическая нормализация и обогащение существующих записей.

У этих групп разные домены, ключи, лимиты и правила оплаты.

## Основные возможности

### Адреса

- интерактивные адресные подсказки;
- очистка и стандартизация адресов;
- прямое и обратное геокодирование;
- поиск по ФИАС/ГАР, КЛАДР и кадастровому номеру;
- определение города по IP;
- поиск почтового отделения;
- идентификаторы города в службах доставки;
- индекс, координаты, административное и муниципальное деление;
- зависящие от тарифа данные: расстояние до МКАД/КАД, кадастровый номер, метро, площадь и оценка стоимости квартиры.

Глубокая стандартизация предназначена для России. Подсказки работают по всем странам как минимум до города; более детальное покрытие документировано для России, Беларуси, Казахстана и Узбекистана.

### Компании и ИП

- поиск по ИНН, ИНН/КПП и ОГРН;
- подсказки по идентификатору, названию, руководителю и адресу;
- статус, юридический адрес и основные регистрационные сведения;
- зависящие от тарифа налоговый режим, численность, учредители, руководители, финансы, лицензии, реестр МСП и другие данные;
- поиск аффилированных компаний на тарифе «Максимальный»;
- отдельные платные продукты «Компания по email» и «Бренд по ИНН».

DaData предупреждает, что налоговая не сообщает КПП филиалов примерно для 25% компаний, поэтому точный поиск конкретного филиала может быть неполным.

### Другие данные

Документированы API для банков, ФИО, телефонов, паспортных справочников, email, автомобилей, налоговых инспекций, судов, таможен и классификаторов.

## Технический доступ

| Поле | «Подсказки» / поиск | «Стандартизация» |
|---|---|---|
| Стиль | HTTP JSON API | HTTP JSON API |
| Типовой base URL | `https://suggestions.dadata.ru/suggestions/api/4_1/rs` | `https://cleaner.dadata.ru/api/v1/clean` |
| Метод | Обычно `POST` | `POST` |
| Авторизация | `Authorization: Token <API_KEY>` | `Authorization: Token <API_KEY>` и `X-Secret: <SECRET_KEY>` |
| Кодировка | UTF-8 | UTF-8 |
| Вызов из браузера | Поддерживается для документированных сценариев подсказок | Не поддерживается из браузерного JavaScript из-за риска раскрытия secret key |
| OpenAPI | Есть | Есть |
| Webhooks | В проверенной публичной документации не найдены | Не найдены |
| OAuth 2.0 | Не найден | Не найден |

### Пример: компания по ИНН

```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -H "Authorization: Token ${DADATA_API_KEY}" \
  -d '{"query":"7707083893","branch_type":"MAIN"}' \
  https://suggestions.dadata.ru/suggestions/api/4_1/rs/findById/party
```

### Пример: стандартизация адреса

Выполняйте только на доверенном backend. Secret key нельзя помещать в браузерный код.

```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -H "Authorization: Token ${DADATA_API_KEY}" \
  -H "X-Secret: ${DADATA_SECRET_KEY}" \
  -d '["мск сухонска 11/-89"]' \
  https://cleaner.dadata.ru/api/v1/clean/address
```

## Ограничения

### «Подсказки» и поиск компаний

- максимальная документированная частота — **30 запросов/с с одного IP**;
- не более **60 новых соединений в минуту с одного IP**;
- длина `query` — **не более 300 символов**;
- дневной объём зависит от тарифа;
- адресные подсказки возвращают максимум 20 результатов;
- оферта запрещает использовать «Подсказки» для автоматической обработки адресов, ФИО и email.

### Стандартизация адреса

- один адрес в запросе;
- максимальная документированная частота — **20 запросов/с с одного IP**;
- не более **60 новых соединений в минуту с одного IP**;
- только backend: браузерный JavaScript не поддерживается из-за риска раскрытия secret key;
- публичная цена — **0,20 ₽ за запись**.

## Доступность и поддержка

Публичная оферта в редакции от 20 апреля 2026 года указывает:

- среднемесячную доступность не ниже **99%**;
- простой в будний день с 08:00 до 20:00 по московскому времени не более **30 минут**;
- возможность продлить период услуги на подтверждённое и признанное время недоступности;
- ответ на вопросы по услугам на форуме в течение **трёх рабочих дней**.

Также работает публичная status page.

Это изложение договорных условий, а не независимое измерение uptime. Atlas пока не рассчитывал фактическую историческую доступность по status page.

## Персональные данные, хранение и права

Оферта утверждает, что при обработке через API DaData не журналирует и не хранит исходные и обработанные данные. Пользователь считается оператором персональных данных, поскольку определяет цели обработки; DaData не считается оператором этих данных в формулировке оферты.

Другие важные положения:

- обрабатываемые данные пользователя названы конфиденциальными и не передаются третьим лицам иначе как по условиям оферты;
- пользователь не вправе передавать права по оферте;
- исключительные права на сайт и данные принадлежат DaData или иным правообладателям;
- оферта не предоставляет явного общего права на распространение или перепродажу возвращаемых данных.

**Интерпретация Atlas:** обычное использование результатов внутри продукта соответствует назначению сервиса, но кэширование, долговременное хранение, распространение, перепродажу и создание конкурирующего информационного продукта необходимо согласовать для конкретного endpoint и источника данных. Наличие API-доступа само по себе не означает право на распространение.

## Независимые преимущества

1. **Очень хороший fit для российских форм.** Адреса, компании, банки, ФИО и email можно подсказывать в одном семействе интеграций.
2. **Российские идентификаторы — полноценные сущности.** ФИАС/ГАР, КЛАДР, ИНН, КПП, ОГРН, ОКВЭД и другие поля поддерживаются напрямую.
3. **Чёткое разделение интерактивной и автоматической обработки.** «Подсказки» предназначены для выбора человеком, «Стандартизация» — для автоматической нормализации.
4. **Хорошая прозрачность.** Есть публичные документация, тарифы, оферта, status page и OpenAPI.
5. **Низкий барьер для прототипа.** Бесплатный тариф даёт 10 000 подписочных запросов в день.

## Независимые недостатки

1. **Не глобальный deep-coverage продукт.** Максимальная глубина относится прежде всего к России.
2. **Стоимость нужно считать по endpoints.** Подписка и списание с баланса могут действовать одновременно.
3. **Годовое обязательство.** Платные подписки приобретаются минимум на год.
4. **Расширенные поля закрыты тарифами.** Учредители, финансовые данные и часть других сведений требуют «Максимального».
5. **«Подсказки» нельзя превращать в дешёвую пакетную очистку.** Документация и оферта отделяют интерактивный ввод от автоматической обработки.
6. **Авторизация ориентирована на аккаунт.** Публичная OAuth-модель с узкими scopes не обнаружена.

## Рекомендация по сценариям

Выбирайте DaData, когда:

- продукт ориентирован на Россию или СНГ;
- важно качество интерактивного ввода;
- полезно получить адресные, корпоративные и контактные операции у одного поставщика;
- нужны ИНН/ОГРН и ФИАС/ГАР/КЛАДР;
- важны бесплатный тариф и простая token-интеграция.

Рассматривайте альтернативы, когда:

- основная задача — глубокая проверка рисков контрагента, а не ввод и обогащение данных;
- нужна подробная глобальная валидация адресов;
- закупка требует индивидуального договора, DPA/NDA или расширенных enterprise-условий;
- перепродажа или распространение ответов является основой бизнес-модели;
- обязательны OAuth scopes и делегированный доступ.

Перед production:

1. перечислите все используемые endpoints;
2. разделите их на подписочные и поштучные;
3. считайте запросы «Подсказок» на одну заполненную форму, а не только формы;
4. проверьте наличие каждого обязательного поля на выбранном тарифе;
5. подтвердите права на хранение, кэширование и распространение;
6. проведите тест качества, нагрузки и обработки ошибок с рабочими ключами.
