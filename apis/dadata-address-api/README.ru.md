## Краткий вывод

**Лучше всего подходит для:** российских форм ввода, CRM/ERP, серверной стандартизации российских адресов и сценариев адрес -> координаты, где полезны поля ФИАС/ГАР/КЛАДР.

**Не подходит, когда:** нужна полная официальная копия адресного реестра, глобальная стандартизация до дома, маршрутизация или автоматическая пакетная обработка через Подсказки.

**Итог:** DaData - сильный первый кандидат для адресных подсказок в России и практичный кандидат для стандартизации и геокодирования. Главный риск закупки - смешать разные endpoint'ы: Подсказки, обратное геокодирование, стандартизация и прямое геокодирование имеют разные цены и лимиты.

## Граница продукта

Эта карточка отделена от [`DaData API`](../dadata/README.ru.md). Существующая карточка остаётся общей и контрагентской. Здесь описаны:

- подсказки адресов;
- стандартизация и очистка адресов;
- прямое геокодирование через стандартизацию;
- обратное геокодирование по координатам;
- поля ФИАС/ГАР, КЛАДР и почтовое обогащение там, где они документированы.

Подсказки компаний, поиск организации и проверка контрагентов остаются вне этой карточки.

## Сценарии

| Сценарий | Fit | Почему |
|---|---|---|
| Подсказки адреса в B2C/B2B формах | Strong | Официальные docs подтверждают поиск по фрагментам, индексу, исправление опечаток и гранулярные части. |
| Нормализация адресов в CRM/ERP | Strong | API стандартизации раскладывает поля, рассчитывает индекс, возвращает координаты и коды реестров. |
| Прямое геокодирование в России | Strong | Официальная страница геокодирования использует endpoint стандартизации адреса. |
| Обратное геокодирование в России | Strong | Документирован endpoint для ближайших домов, улиц и городов по координатам. |
| Пакетная обработка адресной базы | Medium | Нужна Стандартизация, но публично описан один адрес в запросе. |
| Глобальная валидация адресов | Weak | Детальная стандартизация и геокодирование документированы только для России. |
| Маршрутизация | Not applicable | Адресные API DaData не являются routing API. |

## Коммерческие и правовые заметки

- Подсказки предназначены для ввода человеком; документация DaData говорит, что они не подходят для автоматической обработки адресов из базы или файла.
- Стандартизация и прямое геокодирование используют secret key и не должны вызываться из браузерного JavaScript.
- Поставщик сообщает, что данные, обработанные через API стандартизации, не сохраняются; файловые загрузки хранятся временно.
- Хранение, кэширование, redistribution, resale и SaaS embedding нужно подтверждать по конкретному договору.

## Альтернативы

| Альтернатива | Когда лучше | Главный trade-off |
|---|---|---|
| [`Yandex Maps Geocoder API`](../yandex-maps-geocoder-api/README.ru.md) | Геокодирование в связке с картами Яндекса и международным картографическим покрытием | Это не API нормализации; важны ограничения показа и хранения. |
| [`2GIS Geocoder API`](../2gis-geocoder-api/README.ru.md) | Геокодирование в экосистеме карты и каталога 2GIS | Поиск организаций и подсказки - отдельные продукты; кэширование требует проверки. |
| [`FIAS/GAR Data Integration`](../fias-gar-data-integration/README.ru.md) | Собственная адресная база РФ на официальном реестре | Нужны ETL, индекс и логика качества; это не turnkey-подсказки. |

## Рекомендация по сценарию

Выбирайте DaData первым для российских адресных форм и серверной стандартизации, когда важны публичная цена и быстрый старт. Проверяйте альтернативы, если ключевыми становятся связка с картой, международное геокодирование, официальная реестровая база или строгие права хранения.
