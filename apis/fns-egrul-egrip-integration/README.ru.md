# Интеграция ФНС с ЕГРЮЛ и ЕГРИП

[English version](README.md)

> Официальные FTP-архивы XML для загрузки реестров юридических лиц и ИП в собственную информационную систему.

## Краткий вывод

**Лучше всего:** собственное корпоративное хранилище ЕГРЮЛ/ЕГРИП, массовая обработка и полный контроль над ETL.

**Не подходит:** простой запрос по ИНН, готовый JSON, risk-score, связи, суды и закупки без своей инфраструктуры.

**Итог:** первичный государственный feed, а не прямой аналог коммерческого API. Он оправдан при большом масштабе и наличии команды для FTP, XML, нормализации, истории и контроля качества.

## Что предоставляет сервис

- архивы на FTP ФНС;
- XML-файлы юридических лиц и ИП;
- полные сведения от начала реестра до 1 января текущего года;
- ежедневные изменения с 1 января;
- отдельный доступ к ЕГРЮЛ и ЕГРИП;
- описания структуры каталогов и форматов.

ФНС предупреждает, что из-за объёма возможны перебои формирования ежедневных файлов; пропущенные сведения включаются позже.

## Критическое изменение 2026 года

- новые форматы ЕГРЮЛ 4.08 и ЕГРИП 4.07 действуют с 1 февраля 2026 года;
- формальный переходный период завершился 31 июля 2026 года.

Atlas повторно проверил официальные публичные источники ФНС **2026-08-15**. Сейчас публичные материалы противоречат друг другу:

- страницы сервиса всё ещё пишут, что файлы выгружаются и в старых, и в новых форматах;
- те же страницы пишут: с 1 августа 2026 года - только форматы ЕГРЮЛ 4.08 и ЕГРИП 4.07;
- приказ `ЕД-7-14/613@` требует исключительно новые форматы с 01.08.2026.

Credentialed FTP directories и production XML payloads не тестировались, поэтому Atlas не может доказать, какое из утверждений отражает фактическую текущую выгрузку.

## Техническая модель

| Поле | Значение |
|---|---|
| Delivery | FTP-архивы |
| Data format | XML |
| Normative target formats | ЕГРЮЛ 4.08; ЕГРИП 4.07 |
| Пример encoding | `windows-1251` |
| Full snapshot | От начала реестра до 1 января текущего года |
| Incremental | Ежедневные изменения |
| REST/JSON | Нет |
| Webhooks | Нет |
| Авторизация | Атрибуты доступа, пароль, сертификат `.p12` |
| SLA | Не найден; перебои прямо допускаются |

## Полный TCO

Нужно учитывать:

- FTP-клиент и безопасное хранение сертификата;
- загрузку, checksum и распаковку;
- поддержку версий XML;
- idempotency и retries;
- нормализацию и построение актуального состояния;
- историю изменений;
- базу данных, backup и monitoring;
- обработку задержанных файлов;
- юридическую проверку конечного использования.

## Рекомендуемая архитектура

```text
FTP download
    ↓
immutable raw archive
    ↓
checksum + schema validation
    ↓
version-aware XML parser
    ↓
normalized staging
    ↓
entity/change reconciliation
    ↓
current state + history
    ↓
internal API / analytics
```

## Преимущества

- Первичный официальный источник.
- Bulk delivery вместо оплаты каждого запроса.
- История от начала реестров.
- Ежедневные изменения.
- Контроль над собственной моделью.

## Недостатки

- Не REST и не JSON.
- Высокая инженерная нагрузка.
- ЕГРЮЛ и ЕГРИП оплачиваются отдельно.
- Нет готовой риск-аналитики.
- Возможны задержки файлов.
- Неразрешённый конфликт официальных источников о post-cutover delivery formats.

## Юридические вопросы

Хотя сведения открытые и предназначены для информационных систем, отдельно проверить:

- распространение полного массива;
- платный доступ третьих лиц;
- производные базы;
- соединение с персональными данными;
- сроки хранения;
- исторические и исправленные сведения.

Технический доступ не считается автоматическим разрешением на любую перепродажу.

## Альтернативы

- **DaData:** простой JSON и быстрый старт.
- **Контур.Фокус API:** готовый risk-analysis и мониторинг.
- **Seldon.Basis API:** связи, закупки и широкая аналитика.

## Рекомендация

Выбирать прямую интеграцию ФНС после сравнения полного TCO. Она оправдана при больших объёмах, необходимости внутренней копии реестров и готовности поддерживать data pipeline.
