# Report 002

Статус: **Legacy / provenance**

Этот отчет фиксирует dataset-centric refactoring Pass #2. После API-first integration он сохранен как исторический контекст, а не как текущая публичная архитектура Atlas.

Дата: 2026-06-23
Тема: dataset-centric refactoring

## Что исследовано

- Прочитана существующая структура ProjectAtlas после Pass #1.
- Проведена архитектурная миграция от API-centric модели к dataset-centric модели.
- Новое внешнее исследование не проводилось; использованы только уже собранные материалы.

## Что найдено

Из материалов Pass #1 выделены Dataset:

- Метаданные каталога API.
- Реестр компаний и контрагентов.
- Закупки, тендеры и контракты.
- Открытые городские данные Москвы.
- Адресный реестр России.

## Что создано

- `datasets/`
- `providers/`
- `access_methods/`
- `relationships/`
- Новые шаблоны dataset/provider/access.
- Граф связей Dataset -> Provider -> Access -> документация -> стоимость -> лицензия -> альтернативы.

## Какие вопросы появились

- Какие первичные Dataset скрываются внутри `Открытых городских данных Москвы`?
- Где официальная документация Seldon и ФИАС?
- Какие лицензии разрешают хранение, перепродажу, SaaS и обучение ИИ?
- Какие альтернативные поставщики есть у каждого Dataset?
- Какие способы доступа существуют кроме REST API?

## Что исследовать дальше

- Декомпозировать московские открытые данные на конкретные наборы.
- Проверить лицензии и права повторного использования.
- Найти официальные источники и документацию Seldon.
- Найти официальный источник ФИАС и альтернативные способы получения адресных данных.
- Строить дальнейшие проходы от Dataset, а не от API.

## Итог

Project Atlas теперь имеет правильную базовую архитектуру: Dataset является главной сущностью, Provider описывает поставщика данных, Access Method описывает способ получения, а API стал одним из вариантов доступа.
