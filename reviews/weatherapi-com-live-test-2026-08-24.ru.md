# Ревью live-test WeatherAPI.com

[English version](weatherapi-com-live-test-2026-08-24.md)

## Объём ревью

Процедурное pre-merge ревью evidence и raw response files live-test WeatherAPI.com.

## Checklist

- [x] Использован key, предоставленный пользователем; значение key отсутствует в репозитории.
- [x] Core claims зафиксированы до серии запросов и покрывают identity, response contract и procurement/limits.
- [x] До теста изучены документация поставщика и условия API.
- [x] Проверены три класса реалистичных успешных запросов.
- [x] Сохранены запрос с неизвестной локацией и запрос с отсутствующим параметром.
- [x] Raw JSON payloads, HTTP-коды и latency сохранены.
- [x] Исчерпание квоты и нагрузочное тестирование не проводились.
- [x] Расхождение в ответе `current_fields` и четыре варианта синтаксиса зафиксированы как открытый finding.
- [x] Нечёткое сопоставление локации зафиксировано как открытый false-positive/accuracy finding.
- [x] Maturity остаётся `reviewed`; live evidence автоматически не повышает его до `verified`.
- [x] Английская и русская evidence-пары есть; credentials и бинарные файлы не добавлялись.

## Вывод ревью

Evidence подтверждает ограниченный доступ и проверенные формы запросов, сохраняя два открытых интеграционных finding. Квота, rate limits, SLA, точность, цена и data rights не измерены или относятся к договорным условиям. Это поддерживает `live_tested: true` только на ограниченное окно доказательств, но не повышение maturity.

Это процедурное self-review, а не независимое ревью для Gold.

## Рекомендация по merge

Перед merge человек должен проверить raw payloads и два открытых finding. Field-filtering finding нельзя закрывать без уточнения у поставщика или по аккаунту. Key WeatherAPI нельзя считать данными репозитория.
