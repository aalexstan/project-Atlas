# API для интеграции торговых операций

[English version](README.md)

> Сценарное сравнение для создания программ вокруг остатков, заказов, документов и операций маркетплейса.

## Статус исследования

| Поле | Значение |
|---|---|
| Последняя проверка | 2026-08-23 |
| Рынок | Россия |
| Кандидаты | MoySklad JSON API, Wildberries Seller API, Ozon Seller API |
| Live testing | Не проводился |

## Краткий вывод

| Сценарий | Первичный shortlist | Почему |
|---|---|---|
| Операционное ядро компании | MoySklad JSON API | Моделирует остатки, заказы, документы и контрагентов и предназначен для внешних интеграций. |
| Автоматизация только Wildberries | Wildberries Seller API | Даёт продавцу доступ к каталогу, ценам, аналитике и операциям аккаунта Wildberries. |
| Автоматизация только Ozon | Ozon Seller API | Это documented seller-channel интерфейс, но основной reference требует стабильной повторной проверки. |
| Несколько каналов продаж | Сначала MoySklad, затем API каналов | ERP-подобное ядро может хранить общую модель, а API маркетплейсов остаются коннекторами каналов. |
| Минимальная стоимость | Неизвестно | Публичные заявления о доступе к API нельзя напрямую сравнивать с полной стоимостью тарифов, поддержки и эксплуатации. |
| Production-выбор | Оба, по сценарию | До закупки нужны лимиты целевого аккаунта, SLA, права использования и коммерческие условия. |

Единого победителя нет: эти API находятся на разных архитектурных уровнях.

## Матрица сравнения

| Критерий | MoySklad JSON API | Wildberries Seller API | Ozon Seller API |
|---|---|---|
| Класс продукта | Интеграция облачной ERP | Интеграция продавца с маркетплейсом |
| Остатки и склады | Документировано | Документировано для seller scope | Категория документирована, scope открыт |
| Заказы и продажи | Документировано | Документировано для seller scope | Категория документирована, scope открыт |
| Каталог и цены | Документировано | Документировано | Категория документирована, scope открыт |
| Документы и финансы | Документировано | Документировано по категориям сервисов | Категории документированы, scope открыт |
| Операционное ядро нескольких каналов | Более подходящий кандидат | Один канал | Один канал |
| Аутентификация | Basic Auth или access token | Seller API token | Client ID + API key; OAuth для приложений |
| Публичная цена API | Заявлен бесплатный доступ с ограничениями тарифов | Неизвестно | Неизвестно |
| Production-лимиты | Зависит от endpoint и тарифа, точный scope открыт | Зависит от метода, проверены только отдельные примеры | Неизвестны, нужна повторная проверка reference |
| SaaS/модель приложений | Vendor/server solutions документированы | Права использования данных и SaaS неизвестны | Права использования данных и SaaS неизвестны |
| SLA и поддержка | Неизвестно | Неизвестно | Неизвестно |
| Live test | Не проводился | Не проводился | Не проводился |

## Чего это сравнение не устанавливает

- Ozon включён как reviewed-кандидат, но не как полностью проверенный контракт.
- Нельзя считать, что любой API разрешён для платного SaaS без проверки договора.
- Цены веб-продуктов не сравниваются с ценами API.
- Пропускная способность, доступность, качество данных и точность сверки не измерялись.

## Рекомендации по сценарию

- Начинайте с MoySklad, если продукту нужна единая модель остатков, заказов и документов.
- Добавляйте Wildberries как коннектор канала, если бизнес действительно продаёт на Wildberries.
- Для единой панели маркетплейсов сначала определите внутреннюю общую модель, а Ozon используйте после повторной проверки основного reference и получения сопоставимых доказательств.
