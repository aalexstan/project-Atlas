# Geoapify Geocoding API Research Log

## Scope

This log checks whether Geoapify Geocoding API should become an active Atlas profile for the address/geocoding direction as a hosted commercial open-data geocoding provider.

It separates Geoapify from:

- public `nominatim.openstreetmap.org`;
- self-hosted Nominatim;
- official Russian FIAS/GAR registry integration;
- map routing and route matrices;
- Geoapify Places API, which would need a separate profile.

## Observations

- Geoapify is useful for Atlas as a hosted commercial alternative to self-hosted Nominatim when a buyer wants managed international geocoding.
- Its storage-friendly wording is commercially important, but it does not remove the need for ODbL/legal review.
- Geoapify should not be positioned as official Russian address validation.
- The product has enough official evidence for an active reviewed profile, but not for a Gold profile without live benchmarking and legal review.

## Unknowns and Blockers

- Legal treatment of ODbL, derived databases, caching, SaaS embedding and redistribution for a concrete product.
- Whether contract terms differ materially from public terms for paid or enterprise customers.
- DPA/privacy terms for the target customer geography.
- Benchmark quality for target countries, regions, house-level precision, false positives and latency.
- Operational behavior and billing for large batch jobs, failures, retries and duplicates.
- Whether required place-search or POI fields belong to separate Geoapify Places API pricing.

## Live Testing Status

No Atlas credentialed request, benchmark or live API test was performed.

## Profile Decision

Create active reviewed profile `geoapify-geocoding-api`.

Include it in the address/geocoding comparison as a hosted commercial open-data geocoding route. Do not present it as a public OSMF service, self-hosted software, official Russian registry or address-cleaning specialist.
