# Wildberries Seller API Research Log

[Русская версия](2026-08-23.ru.md)

## Scope

Assess whether the official Wildberries seller API is a distinct, useful API-first profile for marketplace operations and internal business-system integration.

## Official sources reviewed

- [API information](https://dev.wildberries.ru/en/docs/openapi/api-information)
- [Russian API information](https://dev.wildberries.ru/docs/openapi/api-information)
- [Token connection guidance](https://dev.wildberries.ru/knowledge-base/articles/019d49a0-f9f7-79a4-b5ee-df5dabe9cff4)
- [Sandbox environment](https://dev.wildberries.ru/en/openapi-other/sandbox-environment)

## Confirmed facts

- The official documentation describes seller-facing API access for integration with ERP, WMS, OMS and CRM systems.
- The documentation is organized around service categories such as content, analytics, prices and discounts, marketplace operations, promotion, feedbacks, supplies, returns, documents, finance and related seller workflows.
- The API documentation is published in Swagger/OpenAPI form.
- Seller account access and API token permissions are part of the documented connection model.
- A test environment is documented for supported scopes and uses generated data.
- At least some methods have explicit method-level examples for request frequency and burst behavior.

## Provider-reported claims

The service categories, integration use cases and test-environment behavior above are descriptions published by Wildberries. Atlas has not independently measured their completeness, availability or production performance.

## Unknowns and blockers

- API-specific pricing and commercial commitments.
- Complete method/field matrix for a target seller account.
- Production quotas outside the documented examples.
- SLA, support response and incident communication.
- Storage, customer display, SaaS embedding and redistribution rights.
- Versioning and breaking-change guarantees for each service category.

## Observations and decision

This is a coherent active API profile for seller-side integrations. It should be evaluated by method category and token scope, not treated as one uniform unlimited API. Create a `verified` profile for the documented core contract, while keeping commercial and operational terms explicitly open.

## Live testing

Not performed. No credentials, seller data or test requests were used by Atlas.
