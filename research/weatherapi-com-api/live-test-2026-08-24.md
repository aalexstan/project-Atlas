# WeatherAPI.com Live Test - 2026-08-24

[Russian version](live-test-2026-08-24.ru.md)

## Purpose

Verify a bounded set of WeatherAPI.com request and response claims with an authorized user-provided free-tier key. This is empirical evidence for the tested request shapes, not a quota, SLA, accuracy or legal benchmark.

## Authorization and safety

- The key was supplied by the user and used once for each request below.
- The key value is not recorded in this repository, logs or raw payloads.
- No paid credential, production secret or personal data was used.
- Five safe HTTP GET requests were made; no load test and no quota exhaustion was attempted.
- The provider documentation and [API terms](https://www.weatherapi.com/terms.aspx) were reviewed before testing. This record does not independently establish the user's account plan or contractual rights.

## Requests and observations

### 1. Current weather with field selection

`GET https://api.weatherapi.com/v1/current.json?key=<redacted>&q=Moscow&current_fields=temp_c,wind_kph`

Observed: HTTP `200`, `0.258207 s`, matched location `Moscow`, Russia. The response included `temp_c` and `wind_kph`, but also returned many other current-weather fields. The documented field-selection parameter therefore requires a separate plan/endpoint clarification; it was not treated as confirmed filtering behavior.

Raw payload: [current.json](live-test-2026-08-24-raw/current.json)

### 2. Three-day forecast

`GET https://api.weatherapi.com/v1/forecast.json?key=<redacted>&q=Moscow&days=3&aqi=no&alerts=no`

Observed: HTTP `200`, `0.683815 s`, matched location `Moscow`, and `3` forecast days. The response was JSON with `location`, `current` and `forecast.forecastday` objects.

Raw payload: [forecast.json](live-test-2026-08-24-raw/forecast.json)

### 3. Search/autocomplete

`GET https://api.weatherapi.com/v1/search.json?key=<redacted>&q=Moscow`

Observed: HTTP `200`, `0.180209 s`, two results. Each observed result contained `id`, `name`, `region`, `country`, `lat`, `lon` and `url`.

Raw payload: [search.json](live-test-2026-08-24-raw/search.json)

### 4. Unknown-looking location string

`GET https://api.weatherapi.com/v1/current.json?key=<redacted>&q=atlas-invalid-location-zzzz`

Observed: HTTP `200`, `0.323943 s`, but the service resolved the string to `Atlas`, Eskisehir, Turkey. This is a material integration finding: a client must validate or review the matched location and must not equate HTTP 200 with an exact query match.

Raw payload: [unknown-location.json](live-test-2026-08-24-raw/unknown-location.json)

### 5. Missing required query parameter

`GET https://api.weatherapi.com/v1/current.json?key=<redacted>&q=`

Observed: HTTP `400`, `0.288702 s`, JSON error code `1003`, message `Parameter q is missing.`

Raw payload: [empty-q.json](live-test-2026-08-24-raw/empty-q.json)

## Rate-limit observation

The five-request sequence did not receive HTTP `429`, `Retry-After` or another rate-limit response. This does not measure the daily quota, burst limit or plan-specific rate limit. Those remain provider-reported or unknown.

## Decision

The test confirms bounded technical access, JSON responses, current/forecast/search request shapes and a structured missing-parameter error. It also found two integration risks: field selection did not visibly narrow the response, and fuzzy location resolution can return a different place with HTTP 200.

Keep maturity at `reviewed`. Set `live_tested: true` only for this evidence window; do not promote to `verified`. The evidence is valid until `2026-11-22` under the shortest 90-day access/limits cadence, unless a material provider change requires earlier review.

See the [procedural pre-merge review](../../reviews/weatherapi-com-live-test-2026-08-24.md).
