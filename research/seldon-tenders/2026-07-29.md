# Seldon.Tenders Research Log — 2026-07-29

## Scope

This research log checks whether the legacy `API Seldon.Tenders` card should become an active API-first Atlas profile, be folded into another active profile, or remain legacy-only until stronger evidence is available.

Legacy material reviewed:

- [catalog/api-seldon-tenders.md](../../catalog/api-seldon-tenders.md)

Official Seldon sources reviewed:

- https://seldongroup.ru/system/1.7/api
- https://seldongroup.ru/functions

- https://seldongroup.ru/news/post/seldon-win-analitika-v-servise-smena-nazvaniya-produkta

The old `api-seldon.ru` URL from the legacy card was not used as a current official source.

| Public API specification, endpoint catalog, authentication, schemas, production limits, SLA, method-level pricing, and API contract terms were not found in reviewed official pages | observed | Reviewed official pages |
| Legacy `api-seldon.ru` history remains a source-risk/provenance note | verified | `catalog/api-seldon-tenders.md` |

## Interpretation

There are two related but distinct public identities:

1. **API.Seldon.Tenders** — an official Seldon procurement-data integration page under Seldon 1.7.
2. **Seldon.Tenders / Seldon.Win** — a procurement-search and analytics web product that was renamed to Seldon.Win.

The current official evidence is enough to know that an API/integration offering exists, but not enough to build an active Atlas API profile without leaving too many developer and procurement essentials as unknown.

## Unknown / Blockers

- Current official endpoint or base URL.
- Authentication model.
- Request and response formats.
- Schemas and complete method catalog.
- OpenAPI/Swagger.
- Rate limits and quotas.
- SLA and support terms.
- Public API-specific pricing and billing units.
- Storage, caching, redistribution, customer-display, affiliate-use and SaaS-embedding rights.
- Whether `API.Seldon.Tenders` is sold as a standalone API product or only as extended Seldon 1.7 functionality.

## Decision

Do not create an active API-first profile yet. Preserve Seldon.Tenders as legacy/provenance until official Seldon documentation, commercial terms, or provider confirmation supports a proper API profile.

This is not a negative product judgment. It is a research-quality decision: Atlas should not create active API cards merely to increase count when specification, authentication, pricing, limits and legal-use facts are not available.
