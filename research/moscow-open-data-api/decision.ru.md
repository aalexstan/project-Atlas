# Решение по Moscow Open Data API

[English version](decision.md)

## Решение

В этом проходе **не создавать** активный API-first профиль Moscow Open Data API.

## Обоснование

Официальная документация для разработчиков по адресу `https://data.mos.ru/developers/documentation` теперь доступна и предоставляет проверенные факты о конечных точках API, параметрах и формате ответа. Условия использования (`https://data.mos.ru/terms`) подтверждают, что данные лицензированы по Creative Commons Attribution 4.0 International (CC BY 4.0) с требованием указания авторства. Однако следующая необходимая информация остается неизвестной или непроверенной:

- метод аутентификации (получение API-ключа требует авторизации/регистрации);
- лимиты, квоты и SLA;
- подробная информация о текущем операционном статусе и процессе поддержки.

Поскольку активный профиль API требует достаточных доказательств как минимум для уровня Verified по всем требуемым аспектам, эти пробелы препятствуют созданию активного профиля на данный момент.

## Статус

Оставить как **legacy/supporting research**. Документация API теперь доступна, предоставляя проверенные факты о:
- конечных точках API (`/v1/datasets/{id}/features`, `/v1/features/{id}`)
- поддерживаемых параметрах запроса (`$top`, `$skip`, `versionNumber`, `releaseNumber`, `bbox`)
- формате ответа (FeatureCollection с объектами GeoJSON, каждый содержащий геометрию (Point) и свойства, включая datasetId, versionNumber, releaseNumber, rowId и Attributes (пары ключ-значение))
- примере использования (доступ к набору данных о открытых ледовых катках)
- лицензии: CC BY 4.0 с требованием указания авторства
- контакте технической поддержки: opendata@mos.ru
- контакте для запроса данных: Хунас Амин Касиевич

Повторно рассматривать возможность создания активного профиля только когда официальные источники подтвердят:
- метод аутентификации и процесс получения API-ключа;
- лимиты, квоты и SLA;
- текущий операционный статус и процесс поддержки.

## Условия повторного открытия

Создавать активный профиль только если официальные источники подтверждают:
- текущую product identity;
- документацию или endpoint;
- аутентификацию;
- поддерживаемые форматы;
- intended use и main operations;
- текущую доступность;
- условия лицензии/повторного использования.
