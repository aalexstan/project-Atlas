# DaData research log — 2026-07-23

## Objective

Create the first reference-quality bilingual Atlas API profile using current primary sources.

## Scope reviewed

- official API directory;
- address Suggestions;
- address cleansing;
- company Suggestions and exact company lookup;
- pricing and plan composition;
- public status page;
- public offer revision dated 2026-04-20;
- provider-organization Python, PHP and C# repositories.

## Method

1. Located official product and method documentation.
2. Separated Suggestions/search from cleansing because credentials, limits and billing differ.
3. Extracted current public pricing and unit prices.
4. Visually reviewed all five pages of the current offer PDF.
5. Confirmed selected SDK repositories through the connected GitHub integration.
6. Marked unsupported claims as unknown.
7. Did not perform live requests because no API credentials were supplied.

## Key decision findings

- DaData is strongest as a unified Russian data-entry and enrichment family, not merely an address API.
- The free tier is substantial for interactive prototypes, but request usage must be modeled per keystroke/form.
- A paid subscription does not include all paid methods; cleansing and several other methods remain balance-based.
- The public offer creates a clear compliance distinction: Suggestions is not for automatic batch processing of addresses, names and email.
- The public offer contains useful API data-handling language, but downstream storage and redistribution rights remain insufficiently explicit for a universal conclusion.

## Not tested

- credentials and signup flow;
- latency;
- accuracy;
- rate-limit behavior;
- error payloads in practice;
- SDK release quality beyond selected repository metadata and Python README;
- corporate package.
