# Исследование: dataset-centric миграция Project Atlas

Статус: **Legacy / provenance**

Этот документ фиксирует историческую миграцию Pass #2 от 2026-06-23. После API-first integration активное направление проекта описано в `docs/MIGRATION.md` и `docs/METHODOLOGY.md`; dataset-centric выводы сохраняются как supporting research.

Дата исследования: 2026-06-23
Статус: архитектурная миграция Pass #2

## Цель

Перестроить Project Atlas вокруг Dataset, а не вокруг API. API должен быть способом доступа к данным, а не главной сущностью базы знаний.

## Что можно сохранить

- `catalog/` полезен как исторический слой Pass #1 и как источник сведений о конкретных API.
- `companies/` полезен как первичная информация о компаниях и организациях.
- `research/apiportal-initial-map.md` полезен как обзор API Portal.
- `research/documentation-link-risk.md` полезен как предупреждение о качестве ссылок.
- `ratings/initial_ratings.md` полезен как API-level рейтинг первого прохода.
- `reports/report_001.md` полезен как отчет о старте проекта.

## Что необходимо изменить

- Главный индекс должен считать Dataset, а не API.
- Provider должен описывать роль в цепочке данных: владелец, сборщик, агрегатор, распространитель, продавец.
- Способ доступа должен быть отдельным слоем: REST API, Open Data, CSV, XML, партнерство, парсинг и другие.
- Лицензия, стоимость и документация должны связываться с конкретным Provider + Access Method, а не только с названием API.

## Что устарело

Устарело как основная модель, но не удаляется:

- `catalog/` как главный каталог проекта.
- `companies/` как главный слой поставщиков.
- Формулировка `API исследовано` как главный показатель прогресса.
- Шаблон `source-card-template.md` как основной шаблон новой карточки.

## Новая структура

- `datasets/` - главные карточки наборов данных.
- `providers/` - поставщики данных.
- `access_methods/` - способы получения каждого Dataset.
- `relationships/` - граф связей Dataset -> Provider -> Access -> документация -> стоимость -> лицензия -> альтернативы.

## Dataset, выделенные из Pass #1

- Метаданные каталога API.
- Реестр компаний и контрагентов.
- Закупки, тендеры и контракты.
- Открытые городские данные Москвы.
- Адресный реестр России.

## Важные ограничения миграции

- Новое исследование API не проводилось.
- Новые факты не добавлялись без подтверждения в материалах Pass #1.
- Широкие Dataset, например `Открытые городские данные Москвы`, помечены как требующие декомпозиции.
- Сомнительные документы Seldon и ФИАС сохранены как риски, а не как подтвержденные официальные источники.

## Вывод

Новая архитектура делает Project Atlas более пригодным для долгосрочного исследования: будущие проходы смогут добавлять поставщиков, способы доступа, лицензии и альтернативы к уже существующему Dataset, вместо того чтобы плодить отдельные карточки под каждый API.
