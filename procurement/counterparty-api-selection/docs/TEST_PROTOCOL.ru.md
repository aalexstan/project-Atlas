# Протокол сравнительного тестирования

[English version](TEST_PROTOCOL.md)

## Цель

Проверить поставщиков на одной выборке, с одинаковыми правилами и одинаковыми обязательными полями.

## Подготовка

1. Заполнить лист **Test Cases**.
2. Подтвердить законность использования идентификаторов.
3. Заморозить список тестов до начала запуска.
4. Зафиксировать тариф, версию API и дату.
5. Синхронизировать часы системы.
6. Убедиться, что тест не нарушает rate limits.

## Выполнение

Каждый тест выполняется минимум три раза:

- холодный одиночный запрос;
- повторный запрос;
- запрос в контролируемой серии.

Для batch выполняются:

- полностью корректный пакет;
- пакет с одним неверным идентификатором;
- смешанный пакет;
- повтор того же пакета.

## Измерения

Записываются:

- полный HTTP или delivery status;
- end-to-end latency;
- число результатов;
- процент обязательных полей;
- точность сопоставления;
- свежесть;
- качество ошибок;
- наблюдаемая стоимость;
- ссылка на raw evidence.

## Правила оценки

### Required Fields %

Количество заполненных обязательных полей делится на число применимых обязательных полей.

`null`, отсутствующее поле и текст «не найдено» должны различаться.

### Match Accuracy 0–5

- 0 — неправильная сущность;
- 1 — результат в основном неверен;
- 2 — существенные ошибки;
- 3 — приемлемо с ручной проверкой;
- 4 — корректно с небольшими оговорками;
- 5 — корректно и однозначно.

### Freshness 0–5

Оценивается только по факту, который можно проверить по первичному источнику на дату теста.

## Запрещено

- менять выборку после просмотра первых результатов;
- считать отсутствующие поля нулевыми;
- сравнивать разные тарифы без пометки;
- скрывать ошибки;
- использовать конфиденциальные данные;
- превышать разрешённую нагрузку.
