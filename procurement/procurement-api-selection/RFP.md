# Procurement API RFP

[Русская версия](RFP.ru.md)

Ask separately for EIS integration and commercial aggregated API routes:

- product boundary, objects and field matrix: notices, lots, participants, protocols, contracts, documents and changes;
- official source list, aggregation method, freshness and historical depth;
- endpoint or file-feed catalog, base URL, authentication and onboarding;
- request/response formats, schemas, versioning, identifiers and error model;
- filtering by notice/contract number, customer, region, category, date and participant;
- full, delta, batch and asynchronous delivery; webhooks or polling;
- update cadence, quotas, rate limits, availability, SLA, support and incidents;
- API-specific price, minimum commitment, overage and document/download billing;
- storage, caching, customer-facing display, redistribution, resale, SaaS and analytics rights;
- personal data, security, retention, DPA and cross-border processing;
- changelog, deprecation and breaking-change policy;
- permitted synthetic or public benchmark access with credentials where needed.
