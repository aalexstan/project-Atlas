# RFP для API торговых операций

[English version](RFP.md)

Ответьте отдельно по операционному ядру, каталогу, остаткам, заказам, возвратам, документам, финансам, аналитике и функциям канала маркетплейса.

1. Какой точный API-продукт, юридическое лицо и типы аккаунтов входят в предложение?
2. Предоставьте актуальную документацию API, base URL, схемы, версионирование и deprecation policy.
3. Перечислите аутентификацию, scopes, роли, срок жизни, ротацию и отзыв токенов.
4. Предоставьте матрицу методов и полей для товаров, цен, остатков, складов, заказов, отправлений, поставок, возвратов, документов, финансов и аналитики.
5. Какие операции синхронные, асинхронные, batch или webhook-based?
6. Предоставьте коды ошибок, правила идемпотентности, retry guidance, пагинацию и рекомендации по сверке.
7. Предоставьте sandbox или тестовый аккаунт, синтетические данные, процедуру сброса и ограничения теста.
8. Предоставьте production rate limits, квоты, concurrency, рекомендации по timeout и порядок обработки инцидентов.
9. Укажите цену именно API, тарифные ограничения, минимумы, overage и оплату приложений или коннекторов.
10. Подтвердите SLA, каналы поддержки, escalation, уведомления о сбоях и срок предупреждения о breaking changes.
11. Подтвердите права хранения, кэширования, показа клиентам, SaaS-встраивания, экспорта, перераспределения и производных данных.
12. Подтвердите обработку персональных данных, DPA, контакты безопасности и требования к хранению/удалению.
13. Для marketplace API уточните владельца seller-аккаунта, доступ между аккаунтами, channel scope и исключение потребительских данных.
14. Для ERP/application platforms уточните модерацию, публикацию, биллинг, установку, удаление и поддержку Vendor-решений.

Разделяйте официальную документацию, стандартный договор, индивидуальные условия, измеренные наблюдения и неизвестные параметры.
