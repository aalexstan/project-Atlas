# Commerce Operations API RFP

[Русская версия](RFP.ru.md)

Please answer separately for the operational core, catalog, inventory, orders, returns, documents, finance, analytics and marketplace-channel functions.

1. What exact API product, legal entity and account types are covered?
2. Provide the current API reference, base URLs, schemas, versioning and deprecation policy.
3. List authentication, scopes, roles, token lifetime, rotation and revocation.
4. Provide the method and field matrix for products, prices, stocks, warehouses, orders, postings, supplies, returns, documents, finance and analytics.
5. Which operations are synchronous, asynchronous, batch or webhook-based?
6. Provide error codes, idempotency rules, retry guidance, pagination and reconciliation recommendations.
7. Provide sandbox or test-account access, synthetic data, reset procedures and test limitations.
8. Provide production rate limits, quotas, concurrency, timeout guidance and incident handling.
9. Provide API-specific pricing, plan restrictions, minimums, overage and charges for applications or connectors.
10. Confirm SLA, support channels, escalation, status notifications and breaking-change notice periods.
11. Confirm storage, caching, customer display, SaaS embedding, export, redistribution and derived-data rights.
12. Confirm personal-data processing, DPA, security contacts and retention/deletion requirements.
13. For marketplace APIs, clarify seller-account ownership, cross-account access, channel scope and whether consumer data is excluded.
14. For ERP/application platforms, clarify app review, publication, billing, installation, uninstall and vendor-support rules.

Distinguish official documentation, standard contract terms, negotiated terms, measured observations and unknowns.
