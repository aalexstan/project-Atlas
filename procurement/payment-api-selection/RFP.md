# Payment API RFP

[Русская версия](RFP.ru.md)

Please answer separately for payment acceptance, refunds, receipts, recurring payments, payment links, payouts, and marketplace/split scenarios.

1. What exact API product and legal entity would contract with the customer?
2. Provide the current API reference, OpenAPI/Swagger, base URLs, versioning and deprecation policy.
3. List authentication, idempotency, error model, webhook events, retries and signature verification.
4. Which payment methods, currencies, countries and merchant categories are supported?
5. Describe one-stage, two-stage, recurring, refund, cancellation, partial refund and dispute flows.
6. Explain receipt/fiscalization responsibilities, 54-FZ integration, and required data fields.
7. Provide sandbox access, test cards/data, test limits and reset procedures.
8. Provide production rate limits, quotas, timeout guidance, incident handling and SLA.
9. Provide the commission table, minimums, failed-payment fees, settlement timing, reserves, chargebacks and overage.
10. Confirm storage, caching, customer display, SaaS embedding, redistribution, data retention and deletion.
11. Confirm personal-data processing, DPA, PCI DSS responsibility split and security contacts.
12. Provide support channels, escalation process, changelog and breaking-change notice period.

Please distinguish public documentation, standard contract terms, negotiated terms, and unknowns.
