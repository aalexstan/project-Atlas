# Messaging API RFP

[Русская версия](RFP.ru.md)

1. Which exact product, legal entity and message channels are included?
2. Provide API reference, base URL, authentication, SDKs, versioning and deprecation policy.
3. Describe send, status, delivery report, callback/webhook, retry, idempotency and error flows.
4. For SMS, provide countries/operators, sender approval, encoding, multipart behavior and DLR semantics.
5. For Telegram or chat channels, describe consent, user initiation, broadcast restrictions and bot/business scope.
6. Provide production throughput, quotas, burst limits, queueing, latency guidance and SLA.
7. Provide price by route, operator, message length, sender, OTP/voice and failed delivery; state VAT and minimums.
8. Confirm opt-out, personal-data processing, retention, deletion, security, DPA and incident notification.
9. Confirm customer display, SaaS, redistribution, reselling and use in multi-tenant products.
10. Provide support, escalation, delivery reports, changelog and breaking-change notice.
